# Мастер подключения и состояние локального аудита

## Цель

Сделать подключение понятным для нового пользователя и дать ему доказуемое
состояние локального сборщика без скрытых операций записи из веб-интерфейса.

## Реализация

1. Сборщик сохраняет небольшой `refresh_status.json` рядом с экспортом:
   время попытки, успешного запуска, ошибка, количество сессий и признак
   неизменности источника.
2. Read-only store читает только этот allowlist-файл и отдаёт `/api/status`.
3. Панель получает статус и показывает:
   - готовность локального аудита;
   - последний успешный запуск;
   - ошибку последнего запуска;
   - следующий ожидаемый запуск по выбранному интервалу.
4. Мастер подключения показывает проверяемые шаги и точную команду для
   регистрации задачи Windows, но не выполняет её из браузера.

## Ограничения

- не читать и не изменять исходные сессии через панель;
- не создавать API-запись и не выполнять PowerShell из HTTP-запроса;
- не считать наличие файла доказательством работы планировщика;
- ошибки показывать явно, без ложного статуса «готово».

## Проверка

Проверить статус API, пустой/ошибочный экспорт, отображение мастера и сценарий
первого запуска в Playwright. Зафиксировать изменения отдельным коммитом.
